# agy 生图测试：一键智能产品精修

一个网页 + 一个本地小程序（`server.js`），用你电脑上已经登录的 agy 给产品图做精修。
测试用，没有数据库、不用安装任何依赖。

## 为什么还有一个 server.js

浏览器出于安全限制，不能直接运行电脑上的程序，所以网页没法自己调 agy。
`server.js` 就是帮网页调 agy 的小程序：只用 Node 自带功能，一条命令启动，关掉终端就停了。

## 运行（Ubuntu 22 桌面，用已经登录 agy 的那个账号）

```bash
cd ai-tutu/tools/agy-refine-test
node server.js
```

浏览器打开 <http://127.0.0.1:5260>。需要 Node 18 或更新的版本（`node -v` 查看）。

可选设置（写在 `node server.js` 前面）：

| 设置 | 作用 |
| --- | --- |
| `PORT=5300` | 换端口（默认 5260） |
| `AGY_PATH=/home/sara/.local/bin/agy` | 页面顶部提示找不到 agy 时，用 `which agy` 查到路径填这里 |
| `AGY_TIMEOUT_SEC=900` | 每张图最长等多久，默认 600 秒，超时自动结束 agy |
| `--lan`（写在后面：`node server.js --lan`） | 让别的电脑也能打开，比如 VMware 外面的物理机，见下一节。等同于 `HOST=0.0.0.0` |

## 从物理机打开（Ubuntu 在 VMware 里，NAT 模式）

NAT 模式下，物理机可以直接访问虚拟机的 IP，**不需要在 VMware 里设端口转发**。

1. 在 Ubuntu 里这样启动：
   ```bash
   node server.js --lan
   ```
   终端会打印出类似这样的地址：
   ```
   其他电脑（比如 VMware 外面的物理机）打开：
     http://192.168.xxx.128:5260    （网卡 ens33）
   ```
2. 在物理机的浏览器里打开这个地址。
3. 打不开的话，按顺序检查：
   - Ubuntu 防火墙：`sudo ufw status`，如果是 active，执行 `sudo ufw allow 5260/tcp`。
   - 物理机（Windows）的“网络连接”里，**VMware Network Adapter VMnet8** 要是启用状态。
   - 物理机能不能 ping 通上面那个 IP（`ping 192.168.xxx.128`）。
4. 虚拟机重启后 IP 可能会变，以每次启动时终端打印的为准。

只有物理机自己（和同一台物理机上的其他虚拟机）能访问到，公司局域网里的其他电脑访问不到。
如果以后要让同事的电脑也能用，需要在 VMware 的“虚拟网络编辑器 → VMnet8 → NAT 设置 → 端口转发”里加一条，
或者把虚拟机网卡改成桥接模式——到时候再说。

**注意**：能打开这个页面的人，都能让 agy 在这台虚拟机上执行操作。测完后不带 `--lan` 重新启动。

## 页面功能

- **产品图**：点击或拖拽上传，最多 50 张（JPG / PNG / WebP），缩略图上显示原图尺寸。
- **精修要求**：可选，原样写进提示词。
- **模型**：启动时执行 `agy models` 读出来的列表，默认选 Gemini Flash。
  这里选的是 agy 里负责看图、写画面描述的模型；画图用的是 agy 自带的生图工具 `generate_image`。
- **背景设置**：白底图 / 原图背景。
- **尺寸比例**：自动、1:1、2:3、3:2、3:4、4:3、4:5、5:4、9:16、16:9、21:9、4:1、1:4。
- **输出尺寸**：800×800（默认）/ 1K（1024×1024）/ 2K（2048×2048）/ 保持 AI 原图。
  比例不是 1:1 时按长边算，例如 3:4 + 800 = 600×800。
  生图工具没有清晰度参数，AI 出图长边约 1024，**2K 是放大出来的，细节不会增加**。
  缩放和补边由浏览器完成，结果区同时显示“AI 原图”和“最终输出”，两张都能下载。

### 测试设置（高级）

| 设置 | 说明 |
| --- | --- |
| 生成方式 | **按原图比例生成，再补边**（默认）：让 AI 按最接近原图的比例出图，不重新构图，产品角度不会变；再由本程序补成所选比例（白底补白色，原图背景补边缘平均色）。**让 AI 直接按目标比例生成**：AI 会重新构图，角度可能变 |
| 调用模式 | **直接调用 generate_image**（默认）/ **委派 image-generator**（agy 内部的生图子智能体）。没出图时自动再试 1 次，第 2 次固定用委派模式 |
| 输出格式 | JPG（质量 92）/ PNG |
| 同时处理几张 | 测速度请用 1 张 |
| 越权即结束 | 默认开。agy 只允许查看原图、生图、委派生图子智能体；一旦运行命令、查看别的文件等，立即结束这一张（然后自动重试） |
| 提示词模板 | 可直接修改。占位符：`{{图片路径}}`、`{{调用说明}}`（按调用模式生成，含 AspectRatio 和 ImagePaths 参数）、`{{背景要求}}`、`{{构图要求}}`、`{{额外要求}}` |

### 结果区

- 每张图显示：原图、AI 原图（标出比例是否符合 ✔/✘）、最终输出（标出“补边”“放大”）。
- 耗时拆成三段：**准备**（开始 → 调用生图）、**生图**（→ 图片写入）、**收尾**（→ agy 结束）。
- 显示每一步调用了什么工具、参数是什么；越权会标 ⚠。
- agy 报 503 之类的错但图已经出来了，算成功，只显示警告。
- **复制结果日志**：设置、每次尝试的耗时、生图实际参数（AspectRatio、ImagePaths、英文 Prompt）、警告、越权记录、图片尺寸，复制后直接发给 AI 分析。

## 结果文件

每张图一个目录：`tools/agy-refine-test/runs/<北京时间>-<随机码>/`

| 文件 | 内容 |
| --- | --- |
| `input.jpg` | 上传的原图（agy 实际用的是系统临时目录里的一份副本，跑完自动删除） |
| `prompt.txt` | 实际发给 agy 的提示词 |
| `agy-output.ndjson` | agy 的原始输出（每行一个 JSON） |
| `out/` | 找到的生成图片 |
| `result.json` | 这一张的汇总（和页面上的结果一样） |

agy 自己也会在 `~/.gemini/antigravity-cli/brain/<会话 ID>/` 保留一份。测完可以直接删掉 `runs/` 目录。

## 这次重点看什么

1. **速度**：“准备”是不是从原来的 2～5 分钟降到几十秒；“生图”本身要多少秒。
2. **角度**：用“按原图比例生成，再补边”时，产品角度和线束走向是否和原图一致。
3. **直接调用 vs 委派**：分别跑几张，对比哪种更快、更稳（调用模式在高级设置里切换）。
4. **越权**：有没有出现 ⚠ 越权；出现的话是什么工具。
