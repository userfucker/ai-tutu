## 2. 目标：复刻 picsetai.cn 的电商作图功能

picsetai.cn 是一个电商 AI 作图网站。Lee 截图了下面 5 个功能（AI 助手看不到网站本身，以下是根据截图整理的）：

### 2.1 一键生成主图 & 详情图组 & 广告图（"AI 全品类商品图"）
- 流程分 5 步，页面顶部有进度：**输入 → 分析中 → 确认规划 → 生成中 → 完成**。
- 左侧输入：
  - 产品图：最多 6 张，提示"多图上传时建议只传必要的视角或 SKU 图，干净的白底产品图最佳"。

  - 详情图要求（文本框）：建议写产品名称、卖点、目标人群、目标电商平台、图片风格；旁边有"AI 帮写"按钮。

  - 模型（默认 Nova 2.0）、尺寸比例（如 3:4 竖版）、清晰度（2K 高清）、生成数量（1 张）。

- 右侧：生成结果区。

## 3. 分析结论（已和 Lee 讨论过）

### 3.1 它的实现原理（推断）
不是"一句话出图"，而是两类模型配合的流水线：

1. **识图分析**（看得懂图片的大语言模型）：识别品类、材质、颜色、卖点、人群、场景。
2. **规划方案**（同一个语言模型）：输出结构化方案——出几张图、每张是什么模块（主图/卖点图/场景图/细节图/尺寸图……）、每张的画面描述、配什么文字、什么版式。
3. **用户确认/修改方案**（"确认规划"那一步）。
4. **逐张生图**（图像模型，把产品图作为参考图传进去），参数：比例、清晰度、张数。
5. 展示、下载。

各功能对应：
- 复刻爆款：参考设计图 + 产品图一起给图像模型，"按参考图的风格和排版，换成这个产品"。
- 服装：衣服 + 模特 + 场景多图合成；"AI 生成模特/场景"是先文字生成一张，再当参考图。
- 精修：图片编辑（去背景换白底、去瑕疵、提清晰度）。
- 翻译：图片编辑（识别文字 → 翻译 → 按原版式重画）。

**真正的核心难点是第 2 步的"规划提示词"**：每个品类出哪些模块、每个模块怎么描述画面。效果好坏主要取决于它，需要反复调。

### 3.2 它用的模型和接入方式（推断）
- 大概率是谷歌 Gemini 系列图像模型（Nano Banana = Gemini 2.5 Flash Image；Nano Banana Pro = Gemini 3 Pro Image），"Nova"是它自己起的名字；IMG 系列也可能是谷歌 Imagen。**都是推断，未核实。**
- **大概率用的是官方 API（或国内 API 中转渠道）**，不是个人账号池。理由：
  1. "标准/快速/极速"三档按速度分价，对应 API 的批量接口（半价但慢）/普通/优先；
  2. 能精确选比例和 2K/4K 清晰度，这是 API 参数；
  3. 菜单里新旧多代模型并存；
  4. 对外收费、大套餐几千张，个人账号池撑不住。
- 价格反推：Nova 2.0 约 ¥0.39–0.56/张，Nova Pro 约 ¥0.49–0.70/张。官方 API 大约价格（凭记忆，以官网为准）：Flash Image 约 $0.039/张（≈¥0.28），3 Pro Image 1K/2K 约 $0.134/张（≈¥0.96）、4K 约 $0.24，批量接口半价。Pro 卖价低于官方原价，推测有折扣渠道或批量接口。

## 4. 关于 agy 的已知事实（上一个项目里实测过）

- 命令：`agy`（Antigravity CLI），用谷歌账号 OAuth 登录。
- 调用方式（实测）：
  ```
  agy --input-format stream-json --output-format stream-json \
      --dangerously-skip-permissions --disable-slash-commands \
      [--conversation <id>] [--model <模型ID>]
  ```
  消息从标准输入发一行：`{"event":"user","message":{"content":"<消息>"}}`。
  也可以 `agy -p "<消息>" --output-format stream-json --dangerously-skip-permissions`。
  - 必须带 `--dangerously-skip-permissions`，否则一遇到工具调用就卡住等审批。
- 输出：NDJSON，一行一个 JSON，顶层 `event`：
  - `init`：`conversation_id`、`init.tools`（工具列表里有 `generate_image`、`view_file`、`write_to_file` 等）。
  - `step_update`：`step_index`、`state`（ACTIVE/DONE）、`step_type`（user_input/agent_response/tool）；tool 步骤带 `tool_name`、`tool_info.parameters`；DONE 时带 `duration_seconds`、`usage`。
  - `result`：`status`、`response`（最终回复全文）、`duration_seconds`、`usage`。**续接会话时 result 里的时长和 usage 是整个对话累计的**，单轮要看本轮各步骤之和。
- **生图（实测）**：智能体自己决定调用 `generate_image` 工具，**参数只有 `ImageName` 和 `Prompt`**（没有比例、清晰度、参考图参数）。耗时一次约 12 秒（文生图猫的例子）。
  - 图片保存在 `~/.gemini/antigravity-cli/brain/<conversation_id>/<ImageName>_<时间戳>.<ext>`，协议和回复里都不给路径，要扫这个目录（同目录还有 task.md 等笔记，只收图片扩展名）。
- `agy models` 能列出模型（模型 ID 带档位后缀，如 `-high/-medium/-low`；列表里还混有非 Gemini 模型）。
- **Ubuntu 桌面版的坑**：在桌面环境登录时，令牌存进了 GNOME 钥匙串，后台服务/沙箱里读不到，报 "authentication required"。解决：隐藏钥匙串后重新登录，令牌就写成文件：
  ```
  bwrap --dev-bind / / --tmpfs /run/user/1000 --unsetenv DBUS_SESSION_BUS_ADDRESS --unsetenv DBUS_STARTER_ADDRESS -- bash -c 'cd /tmp && agy -p "你好"'
  ```
  之后出现 `~/.gemini/antigravity-cli/antigravity-oauth-token` 文件即可。
- **多账号的思路**（未实现）：每个账号一个独立的 HOME 目录（凭证就是 HOME 下的文件），运行 agy 时把 `HOME` 指到那个账号的目录；登录时同样用对应 HOME 跑一次登录。上一个项目里已经用"每个员工一个 AI 家目录、运行前复制凭证文件进去"的方式跑通过类似机制。
- 用量/额度：agy 有 `/usage` 之类的查询，上一个项目里做过 Gemini 用量显示；Lee 的账号是 Google AI Pro（免费账号只显示每周额度）。

### 7.4 插件 0.2.0 + 测试页面（2026-10-09）

- Lee 确认做：白底提纯、提示词去污渍、PNG 透明底 a（镂空开关默认关）+ b（只认纯白、碰到轮廓停）；插件和 agy 测试页面一起（共用 imagekit.js）。
